🐞 Report a bug
  1. Download the session file — it contains the deck, the properties and the current run, and is essential to reproduce the problem.
  2. Open a new issue on GitHub — github issue page ↗
  3. Describe what happened, as specifically as possible:
    • what you did (which buttons, which settings, which seed);
    • which card / game / step is affected (game and step numbers help a lot);
    • what you expected, and what happened instead.
  4. Attach the downloaded file by dragging it into the issue description, then submit.
Writing properties — tips & pitfalls

If the LLM has trouble converting your properties into code

  • Reformulate your prompt — You can try “The commander is in play; it has +1/+1 markers on it” instead of “The commander is on play with +1/+1 markers”, or other versions.
  • Change to another equivalent test — “The Fantasticar's ability that puts tokens into play triggers” is in most cases equivalent to “Four 4/4 tokens arrived into play in a single turn”.
  • Test on controlled cases — If you want to verify that the model compiled your property correctly, test it with a fixed hand that you know should easily verify the property.

Beware your interpretation of probabilities

For instance, consider that you want to approximate the hit probability of Nick Fury, Agent of S.H.I.E.L.D. at turn 5. Here are some possible pitfalls:

  • If you start with a fully random hand, you will instead approximate the probability that, by turn 5, you manage to have Nick into play, one mana of each color available, and a successful hit.
  • If you start with a hand that includes 5 well-chosen lands, you will instead compute the probability that Nick is in play and hits successfully when activated. However, keep in mind how the tool works and its limitations: it will try all possible lines of play until it finds a solution (success), explores everything or timeouts (failure). This means that if there are distinct lines of play that have shuffled the library differently (e.g. using a fetch land), then each of these lines will try activating Nick with a different top of library configuration, which may over-evaluate the probability of success.
  • Note that this is not possible to fully solve this issue. Indeed, stopping the search when Nick's ability is activated for the first time would solve the shuffling problem; however, maybe there was another (still unexplored) line that involved playing a Worldly Tutor putting a valid hit on top of the library before Nick's activation... Still, you can mitigate this issue by enabling the fake shuffling option, which will keep the library in a near-constant order across all possible lines (with the exception of cards known to the user along the line, which are reinserted at random places when shuffling is needed).
  • Conclusion → In all cases, results will be approximated, so be wary of your approximations!
